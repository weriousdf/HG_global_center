# 한결 글로벌문서 센터

해외·국내 간 서류 처리(번역 → 공증 → 아포스티유/대사관 인증 → 발송)를 원스톱으로 안내하고
견적·상담 신청을 받는 웹사이트.

| | |
| --- | --- |
| 고객 화면 | <https://weriousdf.github.io/HG_global_center/> |
| 관리자 화면 | <https://weriousdf.github.io/HG_global_center/admin.html> |
| 데이터 | Supabase (온라인 Postgres) |
| 배포 | GitHub Pages — `main` 브랜치의 `/docs` 폴더 |

> **아직 프로토타입입니다.** 비용 표 금액이 자리표시(`[00,000]원`)이고 사업자 정보가 없어서,
> 검색엔진 수집을 막아 두었습니다. 실제 영업에 쓰려면 아래 "보완할 것" 의 A 묶음을 먼저
> 채워야 합니다.

설정·운영 방법(Supabase 연결, 관리자 계정 만들기, 알림 메일, 배포)은 **[SETUP.md](SETUP.md)**,
설계 판단과 작업 이력은 **[HANDOFF.md](HANDOFF.md)** 에 있습니다.

## 어떻게 돌아가는가

```
고객 브라우저                    Supabase (내 온라인 서버)              나
─────────────                   ────────────────────────              ──
견적 신청 폼
  국가 · 서류 · 인증방식
  이름 · 연락처  ─── HTTPS ──▶  submit_application()
                                      │
                                      ├─▶ applications 표에 저장
                                      │   접수번호 HG-2609-0001 발급
                                      │
                                      └─▶ 알림 메일 ──────────────▶ 메일함
  접수번호 표시 ◀────────────────────┘

진행상황 조회
  휴대폰 번호  ─────────────▶  track_applications()
  단계 표시    ◀────────────    (번호가 맞는 신청만)

                                                        관리자 화면
                                 applications 표 ◀───── 로그인 + 명단 확인
                                                        접수 목록 · 검색 · CSV
```

## 완성된 것

### 고객 화면

**랜딩** — 히어로, 신뢰 수치 5칸(아포스티유 협약국 전체 / 대사관 인증 20개국 / 연 3,000건 등),
개인·기업 진입 카드, 처리 절차 4단계, 하단 CTA.

**서비스 안내** — 개인(B2C)·기업(B2B/B2G) 처리 범위, 서류 태그, 비용 표.

**견적·상담 신청** — 국가 → 서류 → 인증 방식 → 연락처 4단계. 선택하면 예상 절차와 소요일이
바로 바뀝니다. 제출하면 접수번호가 발급됩니다.

* 국가와 서류에 **기타** 가 있어, 목록에 없는 것은 직접 적을 수 있습니다.
  아포스티유 협약국 전체를 처리하는데 칩에 8개국만 두면 나머지 나라 고객이 막히기 때문입니다.
  저장되는 값은 `기타` 가 아니라 직접 적은 이름입니다.
* 연락처는 `01012349876` 으로 적든 `010-1234-9876` 으로 적든 같은 값으로 저장됩니다.
* 무엇이 부족한지 버튼 문구로 알려 줍니다 ("서류 이름을 입력해 주세요" 등).

**진행상황 조회** — 휴대폰 번호로 조회합니다. 그 번호로 접수된 신청이 모두 나오고,
5단계 타임라인(접수 → 번역 → 공증 → 인증 → 발송)이 표시됩니다.

**모바일** — 데스크톱과 같은 화면이 좁은 폭에 맞게 재배치됩니다.

### 관리자 화면

이메일·비밀번호로 로그인하면 접수 목록이 최신순으로 나옵니다. 이름·연락처·접수번호·국가·
서류·요청사항으로 검색하고, CSV 로 내려받을 수 있습니다(엑셀에서 한글이 깨지지 않게 처리).
새로 고쳐도 로그인이 유지됩니다.

### 알림

신청이 저장되면 지정한 주소로 메일이 옵니다. 이름·연락처·국가·서류·인증방식·요청사항이
담겨 있어, 메일만 보고 바로 연락할 수 있습니다.

메일 발송이 실패해도 **신청서 저장은 됩니다.** 고객 쪽이 막히면 안 되기 때문입니다.
(실제로 키를 잘못 넣었던 동안에도 신청은 정상 저장됐습니다.)

### 개인정보를 지키는 방식

이 부분이 가장 공들인 곳입니다. 세 갈래로 권한이 갈립니다.

| 누구 | 무엇으로 | 할 수 있는 일 |
| --- | --- | --- |
| 고객 | 웹페이지에 공개된 키 | 신청서 **저장만**. 읽기·수정은 차단(401) |
| 로그인만 한 계정 | 로그인 토큰 | 아무것도 못 봄 (관리자 명단에 없으면 0건) |
| 관리자 | 로그인 + 명단 등록 | 전체 조회 |

* 웹페이지에 들어가는 키로는 저장 함수 하나만 호출할 수 있습니다. 남의 신청서를 읽을
  경로가 없습니다.
* 관리자 권한은 "로그인한 사람" 이 아니라 **"명단에 있는 사람"** 기준입니다. Supabase 는
  회원가입이 열려 있으면 누구나 계정을 만들 수 있어서, 로그인만으로 권한을 주면 아무나
  고객 정보를 보게 됩니다.
* 진행상황 조회는 **접수번호가 아니라 휴대폰 번호**로 합니다. 접수번호는 `0001`, `0002` …
  순차 발급이라 남의 번호를 찍기 쉽습니다. 휴대폰 번호는 1억 가지여서 찍을 수 없습니다.
  고객이 채울 칸은 똑같이 하나입니다.
* 조회 결과에서 이름은 첫 글자만 남기고 가립니다(`홍**`). 연락처·이메일·요청사항은 아예
  내보내지 않습니다.

## 보완할 것

### A. 영업에 쓰기 전에 반드시 (정보가 필요한 것들)

이 묶음이 채워지기 전에는 검색엔진 노출을 열지 않는 게 좋습니다.

| 할 일 | 지금 상태 |
| --- | --- |
| 비용 표 실제 금액 | `[00,000]원` 자리표시 |
| 제휴 법무법인 수 | "제휴 법무법인" 이라고만 표시 |
| 사업자 정보·연락처 | 푸터에 "확정 후 반영" |
| 개인정보 처리방침 | 없음 — 고객 이름·연락처를 받으므로 법적으로 필요합니다 |
| 로고·사진 | 없음. 여백과 원형 도형으로 처리 중 |
| 검색엔진 노출 열기 | `docs/index.html` 의 `noindex` 와 `docs/robots.txt` 제거 |
| 테스트 데이터 정리 | 이름에 `테스트-삭제해도됨` 이 붙은 행들 |

### B. 기능이 반쯤 열려 있는 곳

**관리자 화면에서 상태를 바꿀 수 없습니다.** 지금은 읽기만 됩니다. `status` 가 계속 `접수` 로
남아 있어서, 고객이 진행상황을 조회해도 5단계 중 1단계만 보입니다. 상태를 넘기려면 Supabase
대시보드 Table Editor 에서 직접 고쳐야 합니다.

목록에서 `접수 → 번역 → 공증 → 인증 → 발송` 을 눌러 넘기는 기능을 붙이면, 고객 조회 화면에
바로 반영됩니다. **남은 것 중 가장 먼저 할 일입니다.**

**신청 폼 항목이 최소한만 있습니다.** 부수, 희망 수령일, 수령 방법(방문/등기/해외 발송),
서류 스캔 파일 업로드가 없어서 상담 전화에서 다시 물어야 합니다.

**서비스 안내가 개괄적입니다.** 서류별 상세(필요 서류, 준비물, 국가별 유의사항)로 넓히면
고객이 전화하기 전에 스스로 확인할 수 있습니다.

### C. 운영하면서 아쉬워질 것

* **조회 시도 제한** — 휴대폰 번호는 1억 가지라 찍기 어렵지만, 아는 번호로는 조회됩니다.
  같은 곳에서 반복 조회하는 것을 막는 장치는 없습니다.
* **접수번호 월 초기화** — 지금은 `HG-2609-0001` 다음 달에 `HG-2610-0006` 처럼 뒷번호가
  이어집니다. 월마다 `0001` 부터 시작하려면 시퀀스를 손봐야 합니다.
* **관리자 화면 메모** — 통화 내용이나 특이사항을 적을 칸이 없습니다.
* **신청 취소·중복 처리** — 고객이 실수로 두 번 넣었을 때 정리할 방법이 없습니다.

## 기타 아이디어

바로 하지 않아도 되지만, 해 두면 일이 줄어드는 것들입니다.

### 손이 덜 가게 만드는 것

**고객에게 접수 확인 메일·문자** — 지금은 김보겸님만 알림을 받습니다. 고객도 접수번호와
예상 일정을 받으면 "접수됐나요?" 문의가 줄어듭니다. 알림 트리거에 한 줄 더 붙이면 됩니다.

**카카오 알림톡** — 국내 고객에게는 메일보다 확실합니다. 단계가 바뀔 때마다 자동으로
보내면 진행 문의가 크게 줄어듭니다. 다만 사업자 등록과 유료 발송 대행사가 필요해서,
위 항목들보다 준비가 무겁습니다.

**견적 자동 계산** — 국가·서류·부수를 고르면 대략의 총액이 바로 나오게 합니다. 비용 표
금액이 확정되면 만들 수 있고, 가격을 미리 아는 고객은 상담 전환율이 높습니다.

**파일 업로드** — 신청 단계에서 서류 스캔을 미리 받으면 왕복이 한 번 줄어듭니다.
Supabase Storage 를 쓰면 됩니다. 다만 원본 서류는 민감한 개인정보라 보관 기간과 삭제
방침을 함께 정해야 합니다.

### 일감을 늘리는 것

**국가별 서류 요구조건 페이지** — "미국 제출 서류에 필요한 것", "베트남 대사관 인증 절차"
같은 페이지를 국가마다 두면 검색으로 들어오는 길이 생깁니다. 김보겸님이 이미 블로그
콘텐츠를 쓰고 계시니, 그 내용을 사이트 페이지로 옮기고 각 페이지 끝에서 신청 폼으로
보내는 구조가 자연스럽습니다.

**블로그 ↔ 사이트 연결** — 네이버 블로그 후기글에서 이 사이트로, 사이트에서 관련 후기글로
서로 링크를 걸면 양쪽 유입이 함께 늘어납니다.

**영어 페이지** — 개인(B2C) 고객에 "외국인 비자 발급 및 국내 체류 수속" 이 들어 있는데,
그 고객들은 한국어 페이지를 읽기 어렵습니다. 신청 폼만이라도 영어로 두면 받을 수 있는
문의가 늘어납니다.

### 알면 도움이 되는 것

**간단한 통계** — 월별 신청 건수, 국가별·서류별 분포. 관리자 화면에 숫자 몇 개만 얹어도
어느 국가·서류가 많은지 보이고, 그게 블로그 글감과 서비스 안내 우선순위가 됩니다.

**재신청 편의** — 한 번 맡긴 고객이 다시 올 때, 휴대폰 번호만 넣으면 이전 정보가 채워지게
합니다. 유학·이민 서류는 여러 번 나눠 처리하는 경우가 많습니다.
